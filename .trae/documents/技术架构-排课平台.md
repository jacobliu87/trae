# 排课平台技术架构文档

## 1. 架构设计

### 1.1 整体架构
采用前后端分离的单页应用（SPA）架构，前端使用 React 生态系统构建，通过 Docker 容器化部署到腾讯云 TKE。

```
┌─────────────────────────────────────┐
│         React Application            │
├─────────────────────────────────────┤
│  ┌─────────┐ ┌─────────────────┐    │
│  │ Pages   │ │ Components      │    │
│  └────┬────┘ └────┬────────────┘    │
│       │           │                  │
│  ┌────▼───────────▼────┐            │
│  │   Zustand Stores     │            │
│  └──────────┬───────────┘            │
│             │                        │
│  ┌──────────▼───────────┐            │
│  │   Services / Utils   │            │
│  └──────────┬───────────┘            │
│             │                        │
│  ┌──────────▼───────────┐            │
│  │   IndexedDB (Dexie)  │            │
│  └──────────────────────┘            │
└─────────────────────────────────────┘

┌─────────────────────────────────────┐
│         Docker 部署架构              │
├─────────────────────────────────────┤
│  ┌─────────────────────────────┐    │
│  │   Nginx (静态文件服务)       │    │
│  │   ← 路由重写 SPA            │    │
│  └─────────────────────────────┘    │
│  ┌─────────────────────────────┐    │
│  │   Node.js Build (构建阶段)   │    │
│  └─────────────────────────────┘    │
│  ┌─────────────────────────────┐    │
│  │   腾讯云 TKE (Kubernetes)   │    │
│  └─────────────────────────────┘    │
└─────────────────────────────────────┘
```

### 1.2 架构层次
- **视图层 (Pages)**: 页面级别的 React 组件，处理路由和布局
- **组件层 (Components)**: 可复用的 UI 组件
- **状态层 (Zustand Stores)**: 基于 Zustand 的全局状态管理
- **服务层 (Services)**: 数据操作、排课算法实现
- **数据层 (Database)**: IndexedDB 持久化（Dexie.js 封装）

## 6. 核心算法

### 6.1 排课算法概述
排课算法负责将课程章节分配到具体的时间段，支持两种模式，并考虑每周课节数限制。

```
算法输入:
  - 课程列表（含 weeklyClassCount）
  - 章节列表
  - 教师列表
  - 时间段列表
  - 教室列表
  - 起始日期、周数、每天课节数

算法输出:
  - 排课记录数组（含自由活动项）
```

### 6.2 课程状态追踪
```typescript
interface CourseState {
  courseId: string;
  units: TeachingUnit[];    // 所有教学单元（章节 x 节）
  nextIndex: number;        // 下一个待分配单元索引
  weeklyCount: number;      // 当前周已排课节数
  weeklyLimit: number;      // 每周课节数上限（来自 Course.weeklyClassCount）
}
```

### 6.3 轮流排课算法
```
1. 构建所有课程的 CourseState，生成教学单元列表
2. 每周开始重置所有课程的 weeklyCount = 0
3. 按天遍历（每周7天），每天按 dailyClassCount 循环
4. 使用 courseRotationIndex 指针轮询选择课程:
   a. 若课程还有未排单元 且 本周未达课节数上限，则分配
   b. 否则跳过，检查下一个课程
   c. courseRotationIndex 移动到下一个课程
5. 若所有课程均无法分配（已达上限或无剩余单元），则插入"自由活动"
6. 为分配的课程选择教师、教室，生成排课记录
```

### 6.4 随机排课算法
```
1. 构建所有课程的 CourseState
2. 每周重置 weeklyCount
3. 每天从符合条件的课程中随机选择:
   a. 筛选条件: nextIndex < units.length && weeklyCount < weeklyLimit
   b. 从符合条件的列表中随机选取一个
4. 若无符合条件的课程，插入"自由活动"
5. 教师分配也从可教该课程的教师列表中随机选择
```

### 6.5 自由活动机制
```typescript
// 当所有课程已达每周课节数上限或无剩余单元时
if (!selectedState) {
  schedules.push({
    id: generateId(),
    courseId: FREE_ACTIVITY_COURSE_ID,  // '__free_activity__'
    // ... 其他字段为空
  });
}
```

## 7. 数据持久化

### 7.1 IndexedDB 数据库
使用 Dexie.js 封装 IndexedDB，数据库名为 `SchedulingPlatformDB`。

| 表名 | 主键 | 索引 |
|------|------|------|
| categories | id | name |
| courses | id | name, categoryId |
| chapters | id | courseId |
| teachers | id | name |
| timeSlots | id | - |
| classrooms | id | name |
| schedules | id | date, courseId, teacherId |

### 7.2 初始化流程
应用启动时自动检查数据库是否为空，若为空则初始化示例数据（3门课程、6个章节、3位教师、9个时间段、3间教室）。

## 8. Docker 部署

### 8.1 多阶段构建
```dockerfile
# Stage 1: Node.js 构建
FROM node:20-alpine AS build
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

# Stage 2: Nginx 运行
FROM nginx:stable-alpine AS production
COPY --from=build /app/dist /usr/share/nginx/html
COPY nginx.conf /etc/nginx/conf.d/default.conf
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```

### 8.2 Nginx 配置
SPA 路由重写，确保所有非文件请求都返回 index.html：
```nginx
location / {
    root   /usr/share/nginx/html;
    index  index.html index.htm;
    try_files $uri $uri/ /index.html;
}
```

### 8.3 CI/CD 流程
GitHub Actions 自动构建部署流程：
1. Checkout 代码
2. Docker 构建镜像
3. 推送到腾讯云 TKE 镜像仓库
4. 通过 Kustomize 部署到 TKE 集群

## 9. 状态管理

### 9.1 Zustand Stores 结构
```
src/store/
├── courseStore.ts         # 课程（含分类）状态管理
├── chapterStore.ts        # 章节状态管理
├── teacherStore.ts        # 教师状态管理
├── scheduleStore.ts       # 排课记录状态管理

```

### 9.2 IndexedDB 持久化
所有数据通过 Dexie.js 操作 IndexedDB，Zustand stores 作为内存缓存层。

```
用户操作 → Zustand Store → Dexie.js → IndexedDB
                          ↕
                    React 组件读取
```
